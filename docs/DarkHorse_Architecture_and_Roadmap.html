1. Target architecture on Azure

Existing code: MCP server, ingest framework and fetchers, grounded agents, LLM proxy. New work: everything on the Azure side, the headless agent service, memory, and the Continuum and ChickletFlow integration points.

2. End-to-end flow

1. Spec approved
An FDS/TDS version is approved in Continuum. A signed webhook calls the agent service (or a developer pulls the spec from the editor).
2. Ground
Agents query the MCP server: hybrid search on AI Search filtered to released APIs, plus memory (past corrections, approved patterns).
3. Generate
Code, TDS and SO agents generate through the LLM proxy to Azure OpenAI, with citations to retrieved sources.
4. Validate
Clean Core verifier, ReviewAgent and ATC checks run; violations trigger rewrite and retry, and are logged as KB gaps.
5. Publish
Artifacts go back to Continuum as a draft version. ChickletFlow moves the chicklet and shows run status and score.

3. Recommendations

Azure, not GCP

The embedder and vector index code is already Azure, clients are Microsoft-heavy, and Azure OpenAI keeps data in the client tenant.

Managed identity everywhere

Drop AZURE_SEARCH_KEY and API keys. Entra ID for users, managed identity between services, Key Vault for the rest.

Retrieval quality first

Hybrid search with the semantic ranker, metadata filters, an eval harness that gates every KB change, then close the coverage gaps.

Memory in two layers

Cosmos DB for session and project state; a second AI Search index for long-term memory (corrections, approved patterns).

Secure ChickletFlow before exposing it

It has no authentication today. Add Entra and service tokens before any ingress to Azure.

One event contract

Agree RICEFW ID mapping, run events and statuses across the three products early (week 2-4) and version them.
